## Authentication

### Definition
**Authentication (AuthN)** is the process of verifying who a user is, whereas **Authorization (AuthZ)** is verifying what specific resources they are allowed to access. *(Authentication ka matlab hai identity check karna ki aap kaun hain, aur Authorization ka matlab hai check karna ki aapko kis data ko dekhne ka permission (rights) hai).*

### Key Concepts
* **AuthN (Who are you?):** Verified via username/password, OTP, or fingerprints.
* **AuthZ (What can you do?):** Verified via user roles (e.g., student vs. principal admin).
* **Common API Authentication Methods:**
  * **Basic Auth:** Client sends username and password encoded in Base64 in the header.
  * **Bearer Token:** Client sends a security token (like a key card) in the header: `Authorization: Bearer <token>`.
  * **API Keys:** A unique static key passed in headers or query parameters.

### Visual Explanation
**The College Library Analogy:**
1. **Authentication:** You show your College ID card at the entry gate. The security guard verifies you are a VJTI student.
2. **Authorization:** You try to enter the Digital Server Room. The admin stops you because only professors are allowed. You are authenticated (a valid student), but not authorized to enter that room.

### Example
#### Code
```javascript
import { test, expect } from '@playwright/test';

test('Basic Authentication API Validation', async ({ request }) => {
  // Access a secure endpoint by passing encoded credentials (Base64)
  const response = await request.get('https://postman-echo.com/basic-auth', {
    headers: {
      // 'postman:password' encoded in Base64 is 'cG9zdG1hbjpwYXNzd29yZA=='
      'Authorization': 'Basic cG9zdG1hbjpwYXNzd29yZA=='
    }
  });

  expect(response.status()).toBe(200);
  const body = await response.json();
  expect(body.authenticated).toBe(true);
});
```
#### Output
```text
  Basic Authentication API Validation (Pass - 160ms)
```

### Real World Usage
When you log into an SBI banking app using a PIN, you are authenticating. When you try to withdraw money, the system checks if you are authorized to deduct money from that specific account number.

### Topic Summary
Authentication verifies identity (credentials), and Authorization restricts access privileges (roles), commonly configured via headers in API test frameworks.

## JWT (JSON Web Tokens)

### Definition
A **JWT (JSON Web Token)** is a compact, URL-safe means of representing claims to be transferred between two parties. The information can be verified and trusted because it is digitally signed. *(JWT ek encrypted ticket ki tarah hai jisme user ki details locked hoti hain. Is ticket par digital signature hota hai taaki koi ise badal na sake).*

### Key Concepts
A JWT is divided into three parts separated by dots (`.`):
1. **Header:** Contains token type (JWT) and signing algorithm (e.g., HS256).
2. **Payload:** Contains user claims (e.g., student roll number, name, department, token expiry time).
3. **Signature:** Generated by hashing the encoded Header, encoded Payload, and a secret key known only to the server. This guarantees the token wasn't tampered with.

```text
  [ HEADER ] . [ PAYLOAD ] . [ SIGNATURE ]
  xxxxx.yyyyy.zzzzz
```

### Visual Explanation
**The University Hall Ticket Analogy:**
When you go to write an exam, you show a Hall Ticket.
* It contains your Name and Roll Number (**Payload**).
* It is signed by the Controller of Examinations (**Signature**).
* If you try to overwrite your roll number with a pen, the invigilator notices that the details don't match the signature, rejecting the ticket. JWT works exactly like this digital hall ticket.

### Example
#### Code
```javascript
// A conceptual representation of decoding a JWT payload in JavaScript
const mockJWT = "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJyb2xsTm8iOjEwMDEsIm5hbWUiOiJSYWh1bCJ9.signatureMock";

// Split and extract the middle part (Payload)
const payloadBase64 = mockJWT.split('.')[1];

// Decode the Base64 payload text back to JSON
const decodedPayload = Buffer.from(payloadBase64, 'base64').toString('utf-8');
console.log(decodedPayload);
```
#### Output
```json
{"rollNo":1001,"name":"Rahul"}
```

### Common Mistakes
* **Storing sensitive data inside JWT payloads:** JWTs are encoded, *not encrypted*. Anyone who intercepts a JWT can decode the Base64 payload in one second. Never put passwords or bank pin codes in JWT payloads.

### Topic Summary
JWT is a secure token format containing encoded claims verified via cryptographic signatures to prevent client-side modifications.

## OAuth Concepts

### Definition
**OAuth (Open Authorization)** is an open standard authorization framework that allows a website or application to access resources hosted by other applications on behalf of a user without exposing their passwords. *(OAuth ek standard system hai jo kisi software ko doosre software se permission lekar data share karne deta hai bina login password share kiye).*

### Key Concepts
OAuth roles:
* **Resource Owner:** The user (you).
* **Client:** The application requesting access (e.g., a book recommendation app).
* **Authorization Server:** The server that authenticates the user and issues access tokens (e.g., Google/Facebook).
* **Resource Server:** The server hosting the user data (e.g., Google Profile API).
* **Access Token:** A temporary secret string used by the client to fetch resource server data.

### Visual Explanation
**The Valet Key Analogy:**
When you give your car to a valet parking driver, you don't hand them your master keys (which open your glovebox, trunk, and home keys). Instead, you give them a Valet Key which only allows driving the car for parking. The **Access Token** is like a valet key—it grants limited access to a specific application without exposing your master account password.

### Example
#### Code
```javascript
// Typical OAuth 2.0 flow step: Exchanging authorization code for an Access Token
import { test, expect } from '@playwright/test';

test('OAuth Token Exchange Simulation', async ({ request }) => {
  const response = await request.post('https://api.vjti.edu/oauth/token', {
    form: {
      grant_type: 'authorization_code',
      code: 'auth_code_from_redirect',
      redirect_uri: 'https://my-app.com/callback',
      client_id: 'vjti-automation-client'
    }
  });

  // Access Token is returned if authorization server accepts credentials
  expect(response.status()).toBe(200);
  const tokenData = await response.json();
  expect(tokenData.access_token).toBeDefined();
});
```

### Topic Summary
OAuth enables secure, limited-scope third-party data sharing using delegated access tokens instead of user account credentials.

## Token Management

### Definition
**Token Management** is the system design pattern of capturing an authentication token after a successful login API call, storing it, and automatically injecting it into all subsequent secure API requests. *(Token Management login API se token ko nikal kar save karne aur aage ke saare calls me Authorization Header me automatically bhejne ka setup hai).*

### Key Concepts
* **Dynamic Injection:** Instead of hardcoding keys, automated tests fetch tokens at runtime.
* **Global Configuration:** Tests can load auth state globally so they don't need to log in before every single test script.
* **Storage:** Tokens are stored in variables, files, or Playwright's state files.

### Example
#### Code
```javascript
import { test, expect } from '@playwright/test';

let authToken = "";

// Login step to fetch token
test.beforeAll(async ({ request }) => {
  const loginResponse = await request.post('https://jsonplaceholder.typicode.com/posts', {
    data: { username: "vjti-admin", password: "securePassword" }
  });
  
  // Simulated token extraction (Assume server returns accessToken)
  const loginBody = await loginResponse.json();
  authToken = "bearer-token-123xyz"; // Mock token from response
});

// Secure API call using the token
test('Fetch Secure Student Directory', async ({ request }) => {
  const response = await request.get('https://jsonplaceholder.typicode.com/posts/1', {
    headers: {
      'Authorization': `Bearer ${authToken}`
    }
  });
  
  expect(response.status()).toBe(200);
});
```

### Topic Summary
Token management handles token extraction and reuse across test hooks to avoid redundant login API invocations.

## API Chaining

### Definition
**API Chaining** is a sequence of API calls where the response parameters of a previous request are extracted and passed as parameters (headers, query params, or body) into the next request. *(API Chaining ka matlab hai ek API se data nikal kar doosre API ke request details me inject karke sequence execute karna).*

### Key Concepts
* Common in automated workflows (e.g. Create Student $\rightarrow$ Get Student $\rightarrow$ Delete Student).
* Requires precise data extraction at each step.
* Helps test integrations and end-to-end user journeys.

### Visual Explanation
**Railway Ticket Booking Flow:**
```text
  [ API 1: Login ]      ──► Extract Token
                              │
  [ API 2: Search ]     ◄─────┘ ──► Extract Train ID ("train-1002")
                                    │
  [ API 3: Book Ticket] ◄───────────┘ ──► Submit Book Order with Train ID & Token
```

### Example
#### Code
```javascript
import { test, expect } from '@playwright/test';

test('API Chaining: Create and Update post workflow', async ({ request }) => {
  // Step 1: Create a new post resource
  const createResponse = await request.post('https://jsonplaceholder.typicode.com/posts', {
    data: { title: 'Initial API Title', body: 'Chaining Demo', userId: 1 }
  });
  expect(createResponse.status()).toBe(201);
  const postData = await createResponse.json();
  
  // Extract resource ID generated by the server
  const createdPostId = postData.id; // e.g. 101

  // Step 2: Use the extracted ID to perform a PUT update request
  const updateResponse = await request.put(`https://jsonplaceholder.typicode.com/posts/1`, {
    data: {
      id: 1, // Using mock endpoint id 1 for actual execution
      title: 'Chained API Title Updated',
      body: 'Chaining Demo',
      userId: 1
    }
  });

  expect(updateResponse.status()).toBe(200);
  const updatedBody = await updateResponse.json();
  expect(updatedBody.title).toBe('Chained API Title Updated');
});
```

### Topic Summary
API Chaining sequences dependent requests together, passing extracted variables from step to step to validate business workflows.

## Data Extraction

### Definition
**Data Extraction** is the technique of parsing structured API response payloads (like JSON or XML) and accessing specific elements, arrays, or keys using paths. *(Data Extraction API ke JSON response se targeted values (jaise id, status, name) ko find aur extract karne ka tareeqa hai).*

### Key Concepts
* **JSON Parsing:** `await response.json()` converts text strings into traversable JavaScript objects.
* **Property Access:** Using dot notation (e.g., `body.student.address.city`) or bracket notation (e.g., `body["student-name"]`).
* **Array Traversal:** Accessing items by index (e.g., `body.items[0].id`) or matching elements using array helper methods.

### Example
#### Code
```javascript
import { test, expect } from '@playwright/test';

test('Data Extraction from Nested JSON API', async ({ request }) => {
  const response = await request.get('https://jsonplaceholder.typicode.com/users/1');
  expect(response.status()).toBe(200);

  const body = await response.json();

  // Extract nested properties
  const cityName = body.address.city;
  const companyName = body.company.name;
  const latitude = body.address.geo.lat;

  // Assert extracted values are correct
  expect(cityName).toBeDefined();
  expect(companyName).toBeDefined();
  console.log(`Extracted Lat: ${latitude}, City: ${cityName}`);
});
```
#### Output
```text
  Extracted Lat: -37.3159, City: Gwenborough
```

### Common Mistakes
* **Accessing properties on undefined paths:** Attempting to read nested keys without checking parent existence (e.g., reading `body.student.profile.grade` when `profile` is undefined). This will crash the test. Always ensure parents exist or use optional chaining: `body.student?.profile?.grade`.

### Topic Summary
Data extraction parses JSON responses to select nested keys, utilizing JavaScript property selectors to feed downstream tests.

## CRUD Validation

### Definition
**CRUD Validation** is an end-to-end API testing pattern that validates the lifecycle of a resource by executing a sequence of Create, Read, Update, and Delete operations on the same database entity. *(CRUD Validation me ek hi resource par sequential operations (Create -> Read -> Update -> Delete) run karke data lifecycle verify kiya jata hai).*

### Key Concepts
* **E2E Consistency:** Ensures database inserts, updates, and deletes are synchronized.
* **Test Isolation:** The resource is created at the start and deleted at the end of the test, leaving the database clean.

### Visual Explanation
```text
  [ POST ]  ──► Create record (Status 201)
                   │
  [ GET ]   ◄──────┘ ──► Verify record exists (Status 200)
                   │
  [ PATCH ] ◄──────┘ ──► Modify field and verify update (Status 200)
                   │
  [ DELETE ] ◄─────┘ ──► Remove record (Status 200/204)
                   │
  [ GET ]   ◄──────┘ ──► Confirm record is gone (Status 404)
```

### Example
#### Code
```javascript
import { test, expect } from '@playwright/test';

test('E2E CRUD Validation Lifecycle', async ({ request }) => {
  // 1. CREATE (POST)
  const createResponse = await request.post('https://jsonplaceholder.typicode.com/posts', {
    data: { title: 'CRUD Post', body: 'Testing CRUD Lifecycle', userId: 1 }
  });
  expect(createResponse.status()).toBe(201);
  const createdRecord = await createResponse.json();
  
  // 2. READ (GET) - Fetch existing post 1 (mocking target entity read)
  const readResponse = await request.get(`https://jsonplaceholder.typicode.com/posts/1`);
  expect(readResponse.status()).toBe(200);

  // 3. UPDATE (PATCH) - Modify field
  const updateResponse = await request.patch(`https://jsonplaceholder.typicode.com/posts/1`, {
    data: { title: 'Updated CRUD Title' }
  });
  expect(updateResponse.status()).toBe(200);

  // 4. DELETE (DELETE) - Remove entity
  const deleteResponse = await request.delete(`https://jsonplaceholder.typicode.com/posts/1`);
  expect([200, 204]).toContain(deleteResponse.status());
});
```

### Topic Summary
CRUD validation executes full Create, Read, Update, and Delete cycles to assert database state consistency from end to end.

## Environment Variables

### Definition
**Environment Variables** are external variables configured outside the codebase (usually in a `.env` file) to store sensitive secrets, configurations, and environment-specific endpoints. *(Environment variables external configs hain jo password, tokens, aur base URLs ko code se alag safe rakhne ke kaam aate hain).*

### Key Concepts
* **Security:** Prevents hardcoding passwords or authorization tokens directly in Git repositories.
* **Flexibility:** Allows switching target test environments (e.g. Staging, Production, Local) without modifying the test code.
* **Configuration:** Loaded in NodeJS using `process.env.VARIABLE_NAME`.

### Example
#### Configuration (`.env`)
```text
BASE_URL=https://api.vjti.edu
ADMIN_TOKEN=vjti-secret-access-token
```
#### Code
```javascript
import { test, expect } from '@playwright/test';
import * as dotenv from 'dotenv';
import * as path from 'path';

// Load environment variables from .env file
dotenv.config({ path: path.resolve(__dirname, '../../.env') });

test('Environment Variables usage', async ({ request }) => {
  // Read base URL and token dynamically at runtime
  const apiBaseUrl = process.env.BASE_URL || 'https://jsonplaceholder.typicode.com';
  const token = process.env.ADMIN_TOKEN || 'fallback-mock-token';

  const response = await request.get(`${apiBaseUrl}/posts/1`, {
    headers: {
      'Authorization': `Bearer ${token}`
    }
  });

  expect(response.status()).toBe(200);
});
```

### Common Mistakes
* **Committing the `.env` file to GitHub:** Adding your `.env` file containing database passwords and production security tokens to version control. Always add `.env` to your `.gitignore` file. Commit a `.env.example` file instead with empty values.

### Topic Summary
Environment variables decouple configuration secrets from test scripts using external `.env` loaders to enforce security best practices.

## Session Summary

### Key Takeaways
1. **Auth Separation:** Authentication verifies user identity, while Authorization checks user permission scopes.
2. **JWT Anatomy:** JWT tokens carry Base64 encoded JSON data secured via a cryptographic signature.
3. **OAuth Delegation:** OAuth exchanges user credentials for delegated access tokens to keep passwords secure.
4. **Automation Chaining:** Extract parameters from prior API responses to build secure follow-up actions dynamically.
5. **Security Isolation:** Never commit `.env` files containing environment secrets to Git; keep keys isolated externally.

### Important Interview Points
* **How do you handle API Authentication dynamically in Playwright?**
  * We trigger a login request inside a `beforeAll` hook, capture the auth token, and pass it dynamically inside headers: `{ headers: { 'Authorization': 'Bearer ' + token } }`.
* **What is the structure of a JSON Web Token (JWT)?**
  * A JWT consists of three dot-separated components: Header (algorithm), Payload (claims like user details), and Signature (security validation hash).
* **What is API Chaining and why is it important?**
  * API chaining is passing response parameters from one API as input to the next API. It is critical for testing multi-step workflows like booking a ticket or completing checkout flows.
* **Why should you never commit `.env` files to git?**
  * `.env` files contain sensitive plain-text API credentials, database keys, and tokens. Committing them exposes database contents to security vulnerabilities.
