## AI in Software Testing

### Definition
**AI in Software Testing** is the application of machine learning algorithms and Large Language Models (LLMs) to automate test script creation, analyze execution failures, generate test inputs, and maintain test frameworks. *(AI in Software Testing ka matlab hai artificial intelligence aur LLMs ka use karke test scripts automatic likhna, failures analyze karna, aur locators verify karna).*

### Key Concepts
* **Test Code Generation:** Writing initial test scaffolding in seconds.
* **Failure Analysis:** Feeding stack traces to AI to get instant root cause explanations.
* **Shift from Writing to Reviewing:** QAs spend less time typing repetitive code and more time reviewing test design coverage.

### Visual Explanation
**The Log Table vs Calculator Analogy:**
In the old days, mathematics students had to look up log values manually using log table booklets, which was slow and prone to counting errors. Today, they use scientific calculators. The calculator doesn't replace the mathematician; it saves them from manual arithmetic so they can focus on solving complex problems. AI in software testing is this digital calculator.

### Topic Summary
AI accelerates the testing lifecycle by taking over repetitive scripting, data creation, and error debugging tasks.

## Prompt Engineering

### Definition
**Prompt Engineering** is the practice of structured communication (designing precise prompts) to instruct Generative AI models to output accurate, contextually relevant source code or documentation. *(Prompt Engineering ka matlab hai AI model ko specific, detailed instructions dena taaki wo sahi aur working code return kare).*

### Key Concepts
* **Role Prompting:** Telling the AI who it is (e.g. "Act as a Senior Playwright Engineer").
* **Context Setting:** Providing files, HTML snippets, or project directories.
* **Constraints definition:** Setting strict rules (e.g. "Do not use XPath, use CSS selectors only").

### Example
#### Prompt
```text
Role: Act as a Senior QA Automation Engineer specializing in Playwright.
Context: I have a login page with HTML input '#reg-no' and button '#submit-btn'.
Task: Write a Playwright test file in TypeScript to fill 'vjti-2026-105' and click login.
Constraints: 
1. Use page object pattern representation.
2. Do not write assertions inside the page object.
```
#### Output (Generated by AI)
```typescript
import { Page } from '@playwright/test';
export class LoginPage {
  readonly page: Page;
  constructor(page: Page) { this.page = page; }
  async login(regNo: string) {
    await this.page.locator('#reg-no').fill(regNo);
    await this.page.locator('#submit-btn').click();
  }
}
```

### Topic Summary
Prompt Engineering uses role prompting and constraints definitions to generate accurate code from AI systems.

## ChatGPT for Test Cases

### Definition
**ChatGPT for Test Cases** is the use of conversational AI to read user requirement specifications (Acceptance Criteria) and output comprehensive lists of positive, negative, and edge-case manual test scenarios. *(ChatGPT ka use karke software requirements se positive, negative aur boundary test cases dynamically generate karna).*

### Key Concepts
* **Requirement parsing:** AI reads bulleted specifications and maps them to scenarios.
* **Edge Case coverage:** AI automatically drafts tests for empty fields, character limits, invalid formats, and boundary inputs.

### Example
#### Prompt
```text
Generate positive and negative test scenarios for a VJTI fee payment gate:
- Input: 10-digit roll number (Format: VJTI-XXXX-X)
- Input: Amount in INR (Min: Rs. 100, Max: Rs. 1,00,000)
```
#### Output
```text
  Manual Test Scenarios:
  1. [Positive] Input valid roll number 'VJTI-2026-1' and amount Rs. 500 -> Verify payment button is enabled.
  2. [Negative] Input roll number with invalid format 'VJTI-202' -> Verify error "Invalid Roll Number Format".
  3. [Boundary] Input amount Rs. 99 -> Verify error "Minimum amount allowed is Rs. 100".
```

### Topic Summary
Conversational LLMs speed up test case writing by mapping acceptance criteria to scenarios, covering edge cases automatically.

## AI Locator Generation

### Definition
**AI Locator Generation** is the process of feeding an HTML raw string snippet to an AI tool to receive stable, unique CSS, XPath, or user-facing Playwright locator strings. *(HTML code snippet se unique aur stable selectors generate karne ke liye AI use karna).*

### Key Concepts
* **Identifying Anchor Elements:** AI detects unique test IDs or role boundaries.
* **Avoiding Auto-Generated Attributes:** AI ignores dynamic attributes (like `id="btn-vjti-987"`) and searches for stable parent nodes.

### Example
#### Input HTML
```html
<div class="row-item">
  <label>Branch Office</label>
  <input type="text" class="form-control" placeholder="Search branch" />
</div>
```
#### Prompt
```text
Generate the most stable Playwright selector for the input element in this HTML snippet.
```
#### Output
```javascript
// AI Recommended locator using user-facing placeholder selector:
page.getByPlaceholder('Search branch')
```

### Topic Summary
AI analyzes HTML nodes to extract stable, user-facing locators while avoiding dynamic attributes.

## Playwright MCP Concepts

### Definition
The **Model Context Protocol (MCP)** is an open standard that allows LLM applications (AI agents) to securely connect to external tools, databases, and filesystem contexts (such as Playwright run commands) to run tests and analyze results autonomously. *(MCP ek standard hai jo AI agents ko system software (jaise Playwright test runners) se connect karke commands run karne aur files edit karne ki permission deta hai).*

### Key Concepts
* **Agentic Integration:** MCP acts as the API bridge between the LLM brain and your computer's terminal.
* **Context Sharing:** The AI agent doesn't just write code; it runs `npx playwright test`, reads the console errors, and edits files directly to fix failing tests.

### Visual Explanation
**The Remote Control Drone Analogy:**
Imagine you are a surveyor.
* **Without MCP:** You walk across a large plot of land, take measurements with a tape, walk back to your desk, write a report, and draw maps manually.
* **With MCP:** You sit in your office and guide a smart drone. The drone flies, uses sensors to survey the area, processes data, and draws the map for you. The drone's remote interface is like **MCP**, letting the LLM (you) manipulate the computer terminal (the land plot).

### Topic Summary
MCP enables agentic coding assistants to interact directly with local terminals and file structures to execute and debug automation tests autonomously.

## Self-Healing Concepts

### Definition
**Self-Healing** is a test automation capability where the framework detects a locator failure during run time, queries an AI engine or backup selector array, identifies the corrected element path, and completes the step successfully without crashing the test run. *(Self-Healing ek aisi technique hai jisme agar runtime par koi button locator change ho jaye, toh script crash hone ke bajaye backup selectors check karke auto-heal ho jati hai).*

### Key Concepts
* **Dynamic Locator Recovery:** If a button's ID changes, the tool looks at backup attributes (like text content, tag type, relative position) to find a match.
* **Rerouting:** Similar to GPS rerouting. If a road is blocked, the GPS finds a detour instead of stopping the car.

### Visual Explanation
```text
  [ CLICK BUTTON ] ──► ID Changed (Error!) ──► [ AI Self-Healing Engine ] ──► Locate via text ──► [ SUCCESS ]
```

### Topic Summary
Self-healing uses backup locator weights to bypass locator failures dynamically at runtime.

## Resume Building

### Definition
**Resume Building** is the process of structuring your professional experience, technical skills, and projects to highlight automation framework design (POM, CI/CD, Docker) to clear IT recruiter screeners. *(Resume Building automation framework projects aur tools ko project details ke roop me high-light karne ka process hai).*

### Key Concepts
* **Prioritize Projects over Lists:** Instead of just listing "JavaScript, Playwright", describe *how* you used them (e.g. "Built a Playwright POM framework, reduced suite runtime by 40% using sharding, integrated GitHub Actions").
* **Action Verbs:** Start project bullet points with action verbs (Implemented, Architected, Automated).

### Example Project Bullet Points
> * *Architected a Page Object Model UI automation framework using Playwright and TypeScript, expanding coverage to 150+ critical user paths.*
> * *Integrated automated testing into GitHub Actions pipelines, reducing regression release cycles from days to under 15 minutes.*

### Common Mistakes
* **Using generic resumes:** Writing "Responsible for manual testing and writing bug reports." Focus on business outcomes and framework architectures instead.

### Topic Summary
Automation resumes should emphasize architectural achievements, framework metrics, and CI/CD pipelines.

## Portfolio Preparation

### Definition
**Portfolio Preparation** is the creation of a public, professional showcase repository (on GitHub) containing clean, documented framework projects that demonstrate your ability to write production-grade test automation code. *(Portfolio preparation GitHub par clean, documented automation projects show-case karne ka process hai).*

### Key Concepts
* **README is the Landing Page:** A portfolio project without a `README.md` file is invisible. Your README must explain:
  - What the framework is.
  - Folder structure.
  - Setup instructions (how to run locally).
  - Configurations (CI/CD, Docker).
* **Code Cleanliness:** Ensure your repository has a `.gitignore` file (no `node_modules` or `.env` checked in).

### Topic Summary
Portfolios demonstrate coding capability through documented, public GitHub repositories featuring clean configurations.

## GitHub Best Practices

### Definition
**GitHub Best Practices** are version control rules (such as writing clear commits, using branch divisions, and formatting project readmes) that developers follow to collaborate on software projects. *(GitHub best practices git histories ko clean rakhne aur systematic repositories maintain karne ke rules hain).*

### Key Concepts
* **Descriptive Commits:** Use prefix conventions (e.g., `feat: add login page POM` instead of `updated code`).
* **Branch Isolation:** Never push code directly to the `main` branch. Create feature branches (e.g., `feature/login-pom`) and merge via Pull Requests.

### Example
#### Commit Message Formats
* `feat: add CustomLoginPage fixture` (Good)
* `fix: resolve secure token extraction bug` (Good)
* `changes` (Bad)
* `fixed script` (Bad)

### Topic Summary
GitHub best practices enforce descriptive commit messages, branch isolation, and project README integrations.

* **How should a QA engineer structure their GitHub portfolio?**
  * Include a comprehensive `README.md` with folder structures and setup steps, a `.gitignore` file to ignore dependencies, a `playwright.config.ts` file, and folders separating page objects, tests, utilities, and CI pipelines.
